# ObenseuerOS code notes

## `src/OsUguiPrototype.cs:OsUguiPrototype.Build`

`src/OsUguiPrototype.cs:OsUguiPrototype.Build` draws the desktop and opens the native Notepad prototype and Minesweeper window through the modding framework's `DesktopUi` API. It is not a replacement for the OS: the remaining desktop apps are not yet ported. Font rendering, shadows, blur, input behavior, scaling, and final appearance need a real Unity comparison. This prototype requires the framework branch that introduces `DesktopUi`.

## `src/OsPlugin.cs:OsPlugin.Awake`

`src/OsPlugin.cs:OsPlugin.Awake` registers the separate computer app only when `Debug/UguiPrototype` is enabled. The existing OS remains available for side-by-side evaluation.

- `src/ToolkitTaskbar.cs:ToolkitTaskbar.Register`, `src/ToolkitTaskbar.cs:ToolkitTaskbar.Unregister` - The desktop supplies its styled grip to the framework resize API and disposes the returned handle when removing a window. The public checks compile the framework handle against UI stubs and Unity managed references.

- `src/ToolkitDesktopMenu.cs:ToolkitDesktopMenu` opens the desktop context menu only on the empty desktop and routes wallpaper, settings, and refresh actions to the existing Toolkit state.
- `src/ToolkitSettings.cs:SelectWallpaper` shares wallpaper selection between Control Panel and the desktop menu while retaining the saved preference.

- `src/ToolkitMinesweeper.cs:LayoutBoard` resizes the existing board on viewport geometry changes without restarting the game; `src/Ugui/MinesweeperLayout.cs:CellSize` retains the 16-pixel minimum for scrolling.

- `src/ToolkitPrototype.cs:Build` applies framework appearance changes to the shell and unsubscribes in `OnDestroy`; `src/ToolkitTaskbar.cs:SetTheme` applies the current palette to existing and newly registered window frames.
- `src/ToolkitSettings.cs:SetTheme` styles Control Panel and updates the wallpaper fallback; explicit plain wallpaper keeps its original blue in both themes. App-specific content remains separately styled.

- `src/ToolkitNotepad.cs:SetTheme` applies the existing OS light and dark palette to the editor, menu, status and open dialogs without changing their content. Dynamic menus and dialogs use the active palette when created; editor and dialog rendering still need in-game verification.

- `src/OsDesktopState.cs:OsDesktopState` owns the shared player name lookup and notification queue outside the legacy WebUi view. `src/OsView.cs:Notify` retains immediate web delivery and fallback queueing; `src/ToolkitPrototype.cs:Update` drains the same queue for an active Toolkit session. Main-menu resets clear the queue.

- `src/Os.cs:IsAvailable` recognizes an active Toolkit desktop even when WebUi is unavailable. `src/OsModApi.cs:IsOpen` and `SyncWindow` check Toolkit first so an active native desktop does not require querying the legacy view to report its visibility.

- `src/Os.cs:Open` recognizes an already-open Toolkit desktop, and `src/Os.cs:Close` uses `src/ToolkitPrototype.cs:DismissNative` to check all active native close guards before closing their registered computer app. The legacy web path remains the fallback.

- `src/NativeDesktopClose.cs:NativeDesktopClose.Dismiss` blocks nested close requests and refuses to close if the active host set changes while guards run. `checks/Launchers/Program.cs:Program.Main` covers guard denial, multiple hosts, reentry and host changes.

- `src/ToolkitPrototype.cs:SessionVisible` distinguishes an active save session from temporary save/load busy status; `src/OsNotepadStorage.cs:SessionCurrent` keeps an autosave from treating the Toolkit desktop as closed or reconciling away native mod windows. `checks/Notepad/Program.cs:Program.Main` covers busy and changed-session states. World placement, input, close guards, and camera restoration still need in-game verification.

- `checks/ToolkitCompile/ToolkitCompile.csproj:Compile` compiles `src/OsLaptop.cs:OsLaptop` against Unity references and game stubs, but does not run the Unity camera, control lock, or host teardown. Those paths require an in-game check.

- `src/ToolkitNotepad.cs:RetainDraft` and `src/ToolkitPrototype.cs:OnDisable` retain unsaved Notepad text in memory when a host is destroyed, including after an approved discard, so a later close-guard veto cannot erase a draft. `src/OsNotepadStorage.cs:RecoveryKey` captures the save folder and session when the host opens; `src/Ugui/NotepadRecovery.cs:List` separates matching drafts from other sessions, and `src/ToolkitNotepad.cs:Recover` requires an explicit choice for either list. Recovered text opens untitled and requires Save As. The buffer is lost on game exit and does not preserve third-party app state.

- `src/ToolkitPrototype.cs:OnDisable` does not retain Mail or third-party app state during forced teardown.

- `src/ToolkitChat.cs:Poll`, `src/ToolkitChat.cs:AddRooms` display chat messages and room names as plain text so markup in a name or message remains visible.
